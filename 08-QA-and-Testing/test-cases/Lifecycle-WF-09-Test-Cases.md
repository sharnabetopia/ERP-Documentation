# Lifecycle WF-09 Test Cases (Asset Acquisition-to-Disposal)

Document status: Draft v0.2 (Phase 2 remediation). Proposed. Test cases are written, **none has been executed**. Every Actual Result is blank and every Execution Status is Not Run.
Test cases in this file: 50. IDs run from TC-0935 to TC-0984, consecutive.
This file supersedes [Asset Test Cases](Asset-Test-Cases.md) for workflow WF-09. That file stays unchanged and still states that no asset test cases existed at Stage 3.
The workflow under test is [WF-09 Asset Acquisition-to-Disposal](../../05-Workflows-and-Diagrams/Lifecycles/WF-09-Asset-Acquisition-to-Disposal.md).
Mix: 14 positive, 19 negative (including permission, self-approval, maker-checker, SoD, closed period and scope), 8 boundary or edge, 6 failure and recovery, 3 end-to-end.

Important limits of these cases:

1. There are no R2 or R3 asset functional requirements, user stories, API paths or permission codes yet. The Requirement ID column therefore lists existing requirement, business rule and rule ids that the workflow depends on. Story ID is n/a unless a real user story exists.
2. Thresholds, depreciation method, useful life, residual value and approval limits in Test Data are placeholders chosen only to make the cases executable. They are not business decisions. They are proposed, PENDING APPROVAL (see section 16 of the workflow).
3. Amounts in the examples were calculated: 12,000.00 divided by 60 months is 200.00, and 1,000.00 over 3 months is 333.33, 333.33, 333.34.
4. Expected results that rely on proposed rules WF09-R1 to WF09-R15 will change if the business decides differently.
5. Priority P0 to P2 follows the [Test Strategy](../Test-Strategy.md). Severity is the impact if the test fails. Steps are separated by line breaks in one cell.
6. Error codes (FIN-002, DUTY-002, STATE-001, AUTHZ-001, FIN-005, FIN-006) are those in the API Documentation. The ledger and period behaviour is tested already for the MVP in [Finance Test Cases](Finance-Test-Cases.md). These cases test the asset flow on top of it.

Common setup used by the Preconditions column is written out in each case so that a QA engineer can run the case alone.
